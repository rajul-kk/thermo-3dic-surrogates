# fieldlint v5: data cards for the held-out acquisition (pre-registration part; Phase B, acquisition only)

Written 2026-10-19 during acquisition (F009 predictions revised the same day after the F009 revert, decision 2b of `protocol_v5.md`; no rule was run), from documentation, file headers, shapes, dtypes and the few statistics named in `protocol_v5.md` section 3. **No fieldlint rule was run on any of these data, not even the F001 integrity check**
(v4 ran F001 as a loader smoke test; v5 did not). Every "Prediction" is derived from documentation, from the rule definitions in `README.md` (`fieldlint --list-rules`) and, where stated, from the already-seen tuning data of the same family.
Provenance labels: **[VERIFIED]** = read from the file, an API or a page in this session; **[DOC]** = stated by the dataset's own paper/README/code; **[MY READING]** = my reading of the dataset's documentation, or my design decision; **[UNVERIFIED]** = not confirmed.
Paths are under `D:\fieldlint_data_v5\` (outside the repository; raw data are not committed).

Format as in `datasets_v4.md`. **Native**: the stored grid is the grid the PDE was solved on; **processed**: resampled/interpolated/normalised after the solve. Presets are staged in `tools/fieldlint/bench/presets_v5_staging/`
(mapping only; passed to the runner by path; not in `src/`, so the v5 code hash is untouched). Converter: `bench/convert_v5.py`; generators: `bench/gen_v5.py`.

**Freshness.** None of these files was opened by any fieldlint version. ConDiff is a family used in v4 (fresh files only). The Well, FlowBench, SISSA and the generated sets are new generator families for the project.

## 2. Cards

### 2.1 ConDiff, six fresh 128 x 128 test files  (in scope, binding)

* **Field / source**: as `datasets_v4.md` 2.1 (HF `condiff/ConDiff`, CC-BY-4.0; Trifonov et al., arXiv 2406.04709; generator `condiff.py` read 2026-10-09). `-div(k grad u) = f`, `u = 0` on the boundary, `k = exp(GRF)` with cubic / exponential / Gaussian covariance and variance in {0.1, 0.4, 1.0, 2.0}, `f ~ N(0,1)` per cell; cell-centred finite volume on exactly the stored 128 x 128 cells. **Native.**
* **Files taken (fresh; none of them used by v4)**: `cubic1.0`, `cubic2.0`, `exponential0.4`, `gaussian0.4`, `cubic0.1`, `exponential1.0`; each 79 056 448 bytes, sha256 equal to the Hugging Face LFS id (section 4), 200 realisations.
* **Mapping, sign convention and index map**: identical to v4 (`v4_condiff`): source = +rhs, u = +x, no negation (positive-definite operator in the code); `x` and `rhs` are flat vectors made with `flatten("F")`, re-indexed with the documented Fortran-order map (a re-indexing, not a repair); k := `k_cell`, the mean of the four corner nodes of the stored 129 x 129 `k` (derived, NOT lossless). The v4 card gives the code citations.
* **Independence**: same family and solver as the five v4 ConDiff files (which are tuning data now): **low independence**; six fresh files of one generator. They are counted as 6 datasets of one family.
* **Prediction**: F001 ok. F002 skipped (the source is sign-changing white noise). F003 applicable, weak (uncertain). F004 ok. F005 ok. F007 skipped. **F008/F009 applicable** (prediction raised from "uncertain" in v4 to "expected" because the five v4 ConDiff files, run once by the frozen v4 rules, gave median operator R^2 0.88-1.00; the high-variance files `cubic2.0` and `exponential1.0` are the least certain).
  Whole-dataset `transpose`/`flip_x`/`flip_y` of `k` and source: detected by F008 where applicable. `shift_index`: F009 (the unchanged v4 rule, 32 evenly spaced samples) is expected to miss it on the 200-sample files in Arm A (descriptive, C6); possibly detected with `--head 32`. Duplicates: detected by F004 (exact copies). The advection probe does not trigger.

### 2.2 Generated chip FEM sets  (in scope by construction, non-binding; T6)

* **What**: `gen_v5.py chip_fem_a` and `chip_fem_b`; own code, fixed seeds, parameters in the script docstring (written before generation). Q1 (bilinear) finite elements on a 65 x 65 node grid of the unit square, `u = 0` (rise) on the boundary nodes, stored temperature `T = 300 + 50 r` K (units K, ambient 300).
  `chip_fem_a`: `-div(k grad r) = q` with a nodal conductivity of 2-4 random rectangles (log-uniform k in [0.2, 10]) on a background of 1 and 1-5 power rectangles; `chip_fem_b`: `-div(grad r) + 5 r = q` (a lumped vertical loss) with Gaussian hot spots plus one rectangle, k = 1 not mapped.
* **Design reason**: an independent discretisation (the exact Q1 element matrix, a 9-point operator on a uniform grid) different from 3D-ICE, HotSpot, the 5-point stencil of F008, and the ConDiff/ELADO solvers. **Non-binding** (decision 4): the project wrote both the generator and the linter.
* **Mapping**: T -> u, power density -> source (>= 0), k -> k (a only), spacing 1/64. All fields share the 65 x 65 node grid.
* **Prediction**: F001, F004, F005 ok; F002/F003 applicable (non-negative source) and ok on clean data; F008/F009 applicable but with R^2 below the ConDiff level (the 5-point stencil is not the Q1 operator; the lumped-loss term of `chip_fem_b` is absorbed by the reaction term of F008); detection of `transpose`, `flip_*` by F002/F003/F008; `unit_slip` detected by F005 (T - 273.15 is below 150 only if the rise is small; here the rise is 50 r with r of order 1, so the slipped maximum is about 30-80 K: the K-range check fires on `hi < 150`); duplicates by F004. The advection probe does not trigger.

### 2.3 SISSA thermal-conduction  (diagnostic, non-binding, processed)

* **Source**: HF `SISSAmathLab/thermal-conduction` (last modified 2025-12-19; **licence field: none; README: only the metadata block** [VERIFIED: blank licence recorded]; used for evaluation without redistribution, user decision 4). Splits `2_stripes.star`, `3_stripes.star`, `4_stripes.star` (the non-refined meshes, 100 snapshots each). sha256 = LFS id (section 4). No author was contacted.
* **Stored [VERIFIED by reading sample 0 and the identity checks]**: geometry config: `points` (1165, 3), z = 0, bounds 0 to 15 in x and y; `cells` (1082, 4) (quadrilaterals, 0-based node indices); `edge_index` (2246, 2); `constraints_values` (131,) and `constraints_mask` (131 node indices): Dirichlet nodes and values (values in [0, 27.35]); `conductivity` (1165,) per node (values [127.7, 381.7] in the first sample). Snapshots config: `steady` (1165,) per node (values in [0, 27.35]), `unsteady` (181, 1165), `times` (181,). The points, cells and Dirichlet-node indices are identical for all 100 samples of a split (one mesh per split).
  Not documented anywhere I could find **[UNVERIFIED]**: the equation (presumably steady/unsteady heat conduction with piecewise conductivity in stripes), the meaning of "star" and "stripes", units, the source term (there is none in the schema).
* **Processing (outside the rules; labelled)**: `convert_v5.py sissa`: scipy `griddata`, linear for the steady temperature and nearest for the conductivity (piecewise constant), onto a uniform 128 x 128 grid over [0, 15]^2; points outside the convex hull of the nodes are filled with the nearest node and recorded in `inside_hull`. **86.3% of the grid cells are inside the hull, 13.7% are filled by the nearest node** (the first attempt, which asserted that all cells were finite, failed on this; the domain is not convex or does not fill [0,15]^2; the fraction was read from the converted file, nothing else was). The three splits are concatenated (2, 3, 4 stripes, 100 each).
* **Mapping**: u := steady, k := conductivity, **no source** (the schema has none; the problem is driven by Dirichlet nodes). Units and ambient unset.
* **Role**: diagnostic: processed, undocumented equation, source-less. **Prediction**: F001 ok; F002/F003 skipped (no source); F004 ok; F005 ok; F008/F009 skipped (no source: "neither the source nor k varies" does not apply since k varies, but with no source the operator fit has no target; if F008 runs it is a surprise). The detection results are therefore not informative about the rules; the set is kept to record that it was evaluated, and what a source-less processed thermal set does to a source-based linter.

### 2.4 The Well, helmholtz_staircase  (control, steady Helmholtz, binding)

* **Source, licence, paper**: HF `polymathic-ai/helmholtz_staircase`, CC-BY-4.0 [VERIFIED README]; Agocs and Barnett, arXiv 2310.12486; code github.com/fruzsinaagocs/bies. The full set is 54.8 GB; **range requests** were used on the 16 train files (2 751 463 424 bytes each; LFS ids in the manifest), the first 13 trajectories each (omega-major order, sorted by file name), frame 0 of `t0_fields/pressure_re` (shape per file: (26, 50, 1024, 256) float32; 50 frames = one period of the analytic time dependence).
* **Equation and BC as documented [DOC]**: `-(Laplace + omega^2) u = delta_{x0}` in a domain above a periodic right-angled staircase, Neumann (sound-hard) boundary, radiation condition at infinity, 16 values of omega in [0.063, 2.51], 32 source positions per omega (x in [-0.4, 0.4], y in [-0.2, 0.4]); the field is complex, `U(t, x) = u(x) exp(-i omega t)`. Frame 0 is `Re u`.
* **What is stored [VERIFIED header of test/omega_04]**: `pressure_re`, `pressure_im` (3 trajectories, 50, 1024, 256) float32, `mask` (1024, 256) float32 (staircase), `scalars/omega`; **the source position is not stored** [VERIFIED].
* **Mapping**: u := Re u at t = 0, **source := the invented uniform 1** (user decision 3: source-less Helmholtz controls keep the uniform source; here a real localised source exists but its position is not in the file), no k (mask would give k = 0 inside the solid: a spurious `k <= 0` error), ambient 0. Grid 1024 x 256 (non-square; the transpose fault is n/a).
* **Prediction**: F001 ok; F002/F003 skipped (uniform source); F004 ok; F008/F009 skipped (neither the source nor k varies). **F005**: the premise (non-negative source, ambient 0) holds and Re u is negative over large regions, so v4 would have warned; v5 is expected to answer with an **info line** from the weak-minimum-principle probe (V >= 0.05 on at least half of the samples; uncertain, since the field is dominated by a point-source singularity and trapped modes: if V < 0.05 on half of the samples the warning stays and C3 fails on this control).

### 2.5 FlowBench lid-driven cavity with heat transfer  (control, steady advective, binding)

* **Source, licence, paper**: HF `BGLab/FlowBench`, **CC-BY-NC-4.0** (non-commercial; the thesis use is fine, state it) [VERIFIED]; Tali et al., arXiv 2409.18032. Files `LDC_NSHT_2D_constant-Re/128x128/harmonics_lid_driven_cavity_X.npz` (125 348 593 bytes) and `..._Y.npz` (442 475 106 bytes); sha256 = LFS id (section 4). Only this one file pair was fetched (user decision 5). Arrays `data`: X (1000, 3, 128, 128) float64, Y (1000, 5, 128, 128) float64.
* **Equation and BC [DOC, paper section 3.2]**: incompressible Navier-Stokes plus heat transfer with the Boussinesq coupling, steady state, 2D lid-driven cavity [0,2]^2 with an object (harmonics shape family) inside; bottom wall T = 1, top wall T = 0, side walls zero heat flux, object surface T = 0; mixed forced convection (lid) and buoyancy (Richardson number). Down-sampled by ParaView from a very fine FEM solution (DendroKT) to 128 x 128 [DOC]. **Advection dominated.**
* **Channel semantics: the stored files do NOT match the paper's Table 12 [VERIFIED].** The table says X = [Re, Gr, g, s] and Y = [u, v, p, theta]. The files hold 3 input and 5 output channels. To identify the channels I read, on the first 50 samples, the per-channel min/max, the number of distinct values in sample 0 and whether a channel is constant per sample:
  X ch0: constant per sample, [1025, 98710] (the Grashof number; Re is constant in this family and omitted); X ch1: continuous, [-0.311, 1.042] (the signed distance field); X ch2: two values, {0, 255} (the geometry mask, 255 inside the object);
  Y ch0 [-1.06, 1.15], ch1 [-1.00, 1.30], ch2 [-5.91, 8.94] (velocity components and pressure), **ch3 [-0.0020, 0.9951] (temperature: the boundary values are 0 and 1)**, ch4 [-2.35, 1.61] with 3 distinct values in sample 0 (unidentified; not used). The identification of ch3 as temperature rests on that range and on the paper; marked [MY READING].
* **Mapping (a user's most plausible reading for a diffusion linter; NOT a documented heat source)**: u := Y ch3; source := X ch2 (the object mask; the object is actually a cold Dirichlet body); no k; ambient 0.0 (the cold-wall level, as for the other controls). The same logic as the other controls: the mapping's source is a reading, not a source in the data. The mask carries the scale 255 as stored.
* **Role / why binding**: the only held-out steady advection-dominated *thermal* control, and the first held-out test of the advection probe (v4 had none).
* **Prediction (honest uncertainty)**: F001 ok; F004 ok. The probe: **expected to trigger** (declined as advective) with moderate confidence (about 60%): the Boussinesq flow carries heat, but the stored temperature is dominated by the two wall boundary layers, and the source I map (the object mask) is not what drives the field, so the stencil fit may be too poor to run (then the R^2 gate declines, which also counts as declined). Risks to C3, stated in advance: if neither gate declines, **F002** (maximum of u is not on the "source", it is the hot bottom wall) can fire; **F005** can warn: the stored temperature has a minimum of about -0.002 (an undershoot of about 0.2% of the range below the ambient 0 and the tolerance is 0.1% of the range), and the weak-minimum-principle probe will not see it (V is about 0.002 < 0.05).
  I register F005 as **likely to warn** (about 55%). This control is binding as the user decided and the outcome is whatever it is.

### 2.6 The Well, acoustic_scattering_inclusions  (control, time-dependent wave, binding with flag)

* **Source, licence**: HF `polymathic-ai/acoustic_scattering_inclusions`, CC-BY-4.0 [VERIFIED README]; code Clawpack; ensemble 283.8 GB; test chunks 36 and 37 (8 111 783 936 bytes each) read by **range requests** (100 trajectories each).
* **Equation [DOC]**: `p_t + K div(v) = 0`, `rho v_t + grad p = 0`, K = 4, reflective walls in x, open in y, density with random inclusions; initial condition: flat pressure plus 1-4 high-pressure rings (intensity U(0.5, 2)).
* **Stored [VERIFIED header of chunk 36]**: `t0_fields/pressure` (100, 102, 256, 256) float32 (102 stored frames; the README says 101 steps), `density`, `speed_of_sound` (100, 256, 256), `velocity`.
* **Mapping (as `v4_pdegym_wave_layer`)**: source := pressure frame 0 (non-negative by the README: flat background plus positive rings **[DOC, not checked]**), u := pressure frame 101 (the last), k := speed_of_sound; ambient 0; run twice, `time_dependent: true` (binding) and unflagged (C3-strict, reported).
* **Prediction**: flagged: F002/F003/F008/F009 skipped "out of scope: time-dependent"; **F005: "below-ambient check not applied"** (info). Unflagged: F002/F003 may fire (the field spreads away from the source); F008 skipped by the R^2 gate or flagged; F005 info through the weak-minimum-principle probe if the late pressure is oscillatory (V >= 0.05) and a warning otherwise.

### 2.7 The Well, rayleigh_benard  (control, time-dependent thermal convection, binding with flag)

* **Source, licence**: HF `polymathic-ai/rayleigh_benard`, CC-BY-4.0 [VERIFIED]; Dedalus code github.com/RudyMorel/the-well-rbc-sf. 35 test files and 35 valid files (1 082 130 432 bytes each) of 5 trajectories each (one (Rayleigh, Prandtl) pair per file); the first 256 trajectories (test files sorted by name, then valid files sorted by name) were read by range requests (frames 0 and 199 of `buoyancy`).
* **Equation [DOC]**: `b_t - kappa Laplace b = -u . grad b`, Boussinesq Navier-Stokes with buoyancy forcing; `b(z=0) = Lz`, `b(z=Lz) = 0` (hot bottom, cold top), no-slip, horizontally periodic; kappa = (Ra Pr)^(-1/2). 2D, 512 x 128, 200 frames. Stored `t0_fields/buoyancy` (5, 200, 512, 128) float32 [VERIFIED header].
* **Mapping**: source := buoyancy frame 0, u := buoyancy frame 199, no k, ambient 0 (the cold top plate); run flagged (binding) and unflagged (strict, reported).
* **Prediction**: flagged: all four steady rules skipped as out of scope; F005 "not applied". Unflagged: F002/F003 can fire; F008 skipped; F005 ok (u >= 0 for b in [0, Lz], so there is nothing below ambient).

### 2.8 Generated advection-diffusion  (control, non-binding; A5)

* **What**: `gen_v5.py advdiff`: `-eps Laplace u + v . grad u = s`, eps = 0.02, per-sample uniform velocity (magnitude U(1,3), uniform angle), first-order upwind convection on a 64 x 64 cell-centred finite-volume grid, u = 0 on the boundary, s = 1-4 Gaussian blobs (>= 0). The global Peclet number is 50-150. 300 samples. Own code, fixed seed, frozen before generation. Mapping: u, source; no k; ambient 0.
* **Prediction**: the advection probe triggers (declined as advective); if it does not, F002/F003/F008 can fire (the maximum of u is displaced downstream of the source). Non-binding; reported as the second sensitivity datum of C7b.
